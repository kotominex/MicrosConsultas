Único punto de entrada: el frontend solo conoce la URL del api-gateway; nunca llama directamente a auth-service o core-service.
JWT stateless: auth-service firma el token (HS256, secreto compartido JWT_SECRET); cada microservicio de negocio lo valida por sí mismo (patrón resource-server) — el gateway no reimplementa autorización.
Database-per-service: auth_db y core_db son físicamente independientes; no hay integridad referencial entre ellas, solo a nivel de aplicación (ver modelo-er.pdf).
Despliegue: todo el stack (incluido el frontend) se construye y levanta con un único comando: docker compose up --build.
